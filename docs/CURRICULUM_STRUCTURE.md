# SQL4Learn — учебный маршрут и методическая приёмка v0.10

**Цель:** выпускник должен не только узнавать синтаксис, но и самостоятельно выбирать зерно данных, строить надёжные метрики, объяснять исполнение запроса и проверять результат на других данных.

**Текущая программа-кандидат 0.10:** девять последовательных модулей, **63 урока и 190 основных SQL-задач**. У каждого урока — объяснение, отдельный трёхшаговый разбор и практическая проверка на двух наборах PostgreSQL; у 16 сложных понятий есть таблицы «до и после». Курс ориентирован на аналитические запросы SELECT; DDL, DML, индексы и транзакции требуют отдельного полноценного практического PostgreSQL-маршрута, а не фиктивных упражнений в read-only редакторе.

## Почему изменили структуру

В публичных курсах [SQLBolt](https://sqlbolt.com/), [SQLZoo](https://sqlzoo.net/wiki/SQL_Tutorial) и [PGExercises](https://www.pgexercises.com/) полезны соответственно ранний интерактивный SQL, проверка нескольких тем и практика на единой связанной схеме. SQL4Learn сохраняет эти общие принципы, но разрабатывает собственный текст, схемы, задания и визуальные разборы. Объективно утверждать, что платформа уже лучше всех конкурентов, до независимой проверки учеников нельзя.

**Ошибки, устранённые в текущем блоке:** отдельное введение LIMIT/OFFSET до сложных отчётов; CASE на отдельных строках до условных групповых метрик; дата-практика перенесена после объяснения DATE/TIMESTAMP; в раннем антисоединении используется уже изученный LEFT JOIN вместо необъяснённого NOT EXISTS; логический порядок FROM → JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT объясняется после знакомства со всеми составляющими. В учебнике контроль качества и fan-out теперь предшествуют сложным продуктовым метрикам.

Не переносили SQL-задачи на новые ID без причины. **Все старые IDs сохранены.** Задание `filter-11` перенесено к `date-types`, чтобы старый выполненный ответ остался засчитанным, но материал времени перестал опережать теорию.

## Стандарт каждого урока

1. **Наблюдаемый результат:** конкретный навык, а не «познакомиться с командой».
2. **Нужные знания:** прямые ссылки на предыдущие темы; свободный просмотр разрешён, но связи видны.
3. **Объяснение и пример:** собственная бизнес-ситуация, настоящие таблицы и SQL, выполняемый в PostgreSQL.
4. **Прогноз:** ученик заранее объясняет результат; может предположить число строк и сравнить с настоящим ответом.
5. **Логическая ошибка:** для каждой темы написан характерный сценарий неверного понимания, а не универсальная подсказка.
6. **Проверка смысла:** вопрос по теории и несколько отдельных SQL-заданий, зачёт по совпадению результата на двух наборах данных.
7. **Завершение:** вопрос для самостоятельного объяснения, переход к следующей теме и накопительная контрольная.

## Автоматические критерии текущей приёмки

- Все уроки имеют уникальный ID, понятную цель, прогноз, типичную ошибку и контрольный вопрос.
- У каждого урока список prerequisite с проверкой, что все эти темы **строго раньше** в учебном маршруте.
- Модули и накопительные контрольные расположены по одной последовательности, а не по истории добавления файлов.
- Раннее антисоединение не требует NOT EXISTS. Дата-задание `filter-11` находится только после темы DATE/TIMESTAMP.
- Для всех примеров и эталонных запросов выполняются настоящие PostgreSQL-тесты на исходном и альтернативном наборе данных.
- Браузерный тест проверяет маршрут, прогноз, ранее усвоенные задания, новые примеры и реальную проверку SQL.
- Нельзя объявлять релиз успешным до validate, deploy и browser-smoke в GitHub Actions.

2. Сделать диагностику неправильного результата более предметной: сравнение отдельных строк, значений, ошибок зерна без открытия эталонного SQL заранее.
3. Проверить, что 190 задач действительно отличаются способом мышления, а не только формулировками; усилить самые слабые темы по реальным данным прохождения.
4. Отдельно построить курс PostgreSQL с изменением схемы/данных, EXPLAIN и индексами, если цель — полный SQL за пределами аналитических SELECT.

## Честно о следующих пробелах

Это сквозной **педагогический каркас** всего учебника, но не независимая экспертная сертификация содержания. Ещё нужно проводить пробные прохождения реальными новичками, собирать данные об ошибках/сложности каждого задания, добавлять разнообразные независимые наборы данных для нескольких профессиональных доменов, создавать упражнения на диагностику неверных SQL-планов и проверять качество объяснений через результаты обучения. Интервальное повторение выпущено в 0.7: девять навыков, 27 независимых формулировок, интервалы 1/3/7/30 дней. Это работающий начальный механизм, но ещё не исчерпывающая адаптивная система: не хватает большего разнообразия и независимой оценки долгосрочного освоения.
