# Повторение SQL — продуктовая политика v0.7

## Назначение

Проверять, способен ли студент спустя время снова самостоятельно решить задачу из уже изученной темы, а не только воспроизвести эталон в день урока. Это дополнительная практика, **не самостоятельная профессиональная аттестация**.

## Что реализовано

- 9 тем: первые выражения, условия, агрегаты, JOIN, даты, CTE, окна, продуктовая аналитика, качество данных.
- По 3 оригинальных формулировки на тему, всего 27 реальных SQL-запросов; проверка результатов в PostgreSQL на двух наборах данных.
- Тема становится доступна после хотя бы одной реально решённой задачи соответствующего урока; непройденные темы не показывают доступный редактор.
- После 1-го/2-го/3-го/4-го правильного ответа следующая попытка назначается через 1/3/7/30 дней соответственно. Повторное успешное выполнение после четвёртого цикла поддерживает 30-дневный интервал.
- После неправильного результата уровень повторения сбрасывается на 0, счётчик ошибок увеличивается, задачу можно исправить сразу.
- При повышении уровня следующая формулировка выбирается циклически из трёх вариантов. Одну и ту же готовую строку SQL нельзя автоматически перенести в новое упражнение: редактор очищается.
- В пользовательском прогрессе хранятся `review[skillId] = {level, nextDueAt, misses}` и черновики; старые записи `sql4learn-progress-v1` без поля `review` остаются совместимыми.
- Доступность проверяется, когда пользователь открывает страницу. Фонового сервера, уведомлений и сравнения прогресса между устройствами нет.

## Ограничения

Три варианта на тему — ограниченный набор; при долгом обучении формулировки будут повторяться. Уровень 4 означает **четыре успешные контрольные попытки**, а не доказательство владения предметом. Изменённый SQL-набор хранится в браузере, а не на секретном сервере.
